# Local static evidence workbench

The workbench reads captured static source through the existing supervisor. It does not execute/import a target, call a model, diagnose a root cause or repair files. Reading completed means the requested reading completed; it is not a whole-repository verdict.

Start it explicitly from the trusted installation, outside the project being read:

```sh
agent-review evidence-ui --data-root /local/owned/macr-evidence
```

Choose an actual owned local directory. The command prints a loopback URL including a short-lived session fragment. Open that complete URL manually. The app removes the fragment from the address bar and keeps its access credential in this tab's sessionStorage. Do not share the bootstrap address. No browser opens automatically, no data is sent off-machine, and no third-party runtime dependency or Node build is required.

The default data root is `~/Library/Application Support/MACR Evidence`. It is created only when the command runs. macOS APFS is the primary root environment; a limited set of Linux local POSIX filesystems is recognized for protocol fixtures, which does not establish Linux native worker/pressure support. Windows and shared/network/ExFAT data roots are unsupported. Existing source exclusions and symlink policies still apply. A supported filesystem name alone does not prove a tested configuration.

Fill in an absolute project directory and a nonblank question, then add source entries, qualified symbols or an already-reported traceback. Entries can name a file, `file:qualified_symbol`, `file:line` or `file:start-end`. Question limit is8KiB UTF8, traceback64KiB/64frames, entries+symbols6. The standard profile has a120-second analysis target and5-second cleanup target; the larger profile has240 seconds and larger resource budgets. Targets are not hard guarantees against kernel/device stalls. No profile is raised automatically.

The single page provides input, phase/elapsed time and cancellation, captured source with exact physical lines and completeness, coverage/required gaps, local retained history and original JSON/Markdown downloads. It does not invent file progress or percentages. `coverage.unread` means source not selected for display; those files may have been captured and parsed. Frames and unique source units are counted separately. A valid v2 frame may still reference a partial function body; unsupported parsing or limited syntax is not a diagnosis of a target defect.

An uncommitted analysis failure exposes a bounded code/field/stage summary and, when present, the original effective/observed limit. It remains a failure; source panels and successful exports remain unavailable. The summary is retained for new runs without another target read or dispatch. Older records without it explicitly show that the stage was not recorded. Metadata entry/byte limits count cumulative traversal work, including repeated owned-output monitoring; they are distinct from the number of entries in the retained directory. The unchanged standard/larger profiles share the same20000 metadata-entry and4MiB metadata-byte budgets. The manually selected `standard-capacity` workbench preset uses the existing standard profile with exactly two overrides:100000 cumulative metadata entries and16MiB cumulative metadata bytes. Other standard budgets, exclusions, worker logic,0.1-second allocation checks and0.05-second RSS target stay unchanged. The UI labels the preset before submission; state/history and saved core request/receipt/report retain the full effective profile. Reopening accepts only an exact registered preset, and altered capacity or other fields are rejected. It never selects the preset automatically after a failed run. Its capacity is finite and does not guarantee completion under the time or other guards.

There is one non-daemon supervisor execution thread and at most one analysis worker, with no automatic retry, restart or queue. Duplicate intent resolution returns the same run. An uncertain submission is queried rather than posted again. A cancel response means cancellation was requested; closure must still be confirmed. A cancellation arriving after valid COMMITTED preserves the completed/partial saved result. Unknown closure blocks another analysis and is retained across startup; no PID from a saved record is blindly killed.

Use **Exit workbench** or interrupt the foreground command to request cancellation and wait for supervisor cleanup. Closing a browser tab alone does not cancel a run. SIGTERM requests the same graceful path. Forced process death cannot establish worker closure: startup inspects the owned registry/receipts and isolates unresolved runs instead of replaying them.

Only this workbench's registered outputs appear in history. Reopening reads the saved snapshot even if the original project moved; it never substitutes current working-tree bytes. A read-only consumer binds the original receipt, documents, manifest and every captured file, and checks displayed excerpt bytes. It does not rebuild AST or re-prove the original semantic observations. Damaged/version-unsupported/budget-stopped readings are distinct and withheld, with original files preserved. Hash associations are not digital signatures or a guarantee against later tampering.

Saved JSON contains worker-render usage. Run details separately show the returned final lifecycle/cumulative usage when retained; these are not the same measurements. Exports are original verified JSON/Markdown bytes, with local paths, input and selected source; handle them as local sensitive material. Export errors do not rerun analysis or revoke a committed result.

The data root is held by a fixed-file-descriptor cross-process lock until shutdown. A second owner is refused. Retained physical allocation is capped at2GiB; a new run reserves its profile allocation maximum plus8MiB metadata/allocation margin. Owned metadata is capped at5MiB. No existing output is overwritten and nothing is automatically deleted. Capacity refusal requires inspection/manual handling of the specific owned old outputs. Whole-root checks are bounded by10 seconds,100000 entries and16MiB estimated metadata. Read-only report verification is serial, up to256MiB IO and a10-second target, using the original metadata limits; during analysis only an already-loaded old report can be read in the browser.

The HTTP adapter binds only127.0.0.1 on an ephemeral port, caps connections at4 before starting request threads, socket operations at10 seconds, headers at16KiB and bodies at128KiB. All API reads/writes require the session credential and exact Host. POST additionally requires exact Origin; GET may omit Origin, but an Origin that is present must match. There is no CORS, directory server, arbitrary-path file endpoint or external asset. Packaged HTML/JS/CSS are the only page source; missing resources fail rather than falling back to cwd or the target. Captured text is rendered as text, and source line numbers follow LF/CRLF/CR physical boundaries.

Validation must distinguish bounded pure branch fixtures, real loopback transport, actual native supervisor/pressure/RSS/closure, installed-resource checks and browser experience. Pure/mocked branch outcomes are not native acceptance. The previous installed-r3 macOS24/24 result does not itself validate this UI. Exact new native/browser results are recorded separately. The second external real project and sustained/larger-load performance remain separate unrun scope; no model/VM/target-code acceptance is added.
